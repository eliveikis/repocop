# Archived changes named by when they finished

## Requirement

As a developer, I want each archived change's file name to start with the UTC date and time it was archived, so that the archive lists changes in the order they finished, and a change without an id still has a unique, dated name.

## Acceptance Criteria

1. `/complete-change` archives a change as `archive/<YYYY-MM-DDTHHMMSSZ>-<name>.md`, for example `2026-10-14T150616Z-req-12-bulk-import.md`, the time in UTC, keeping the rest of its name.
2. The skill makes the move with one call to a script beside it, so no tokens go on working out the name or the move.
3. The coordinator still shows an archived requirement as archived and reads its text, and never gives out an id that an archived file already has.
4. The changes already in this repository's archive are renamed by the time git recorded for each move, and links to them still work.

## Out of scope

- Subfolders in the archive.
- Renaming archives in other repositories. Each gets the new skill through template sync, and its old archives keep their names.

## Implementation Notes

- The stamp is `date -u +%Y-%m-%dT%H%M%SZ`: the date stays readable, `T` and `Z` mark the time as UTC, it sorts in order, and it has no colons, which Windows file names don't allow.
- The script is `.claude/skills/complete-change/archive.sh <change path>`, in POSIX `sh`. It takes the stamp from `date -u`, `git mv`s the file into the `archive/` folder beside it, prints the new path, then prints the files that still mention the old one, from `git grep`. The skill fixes those links and commits, as it does now.
- The script is allowlisted in this repository's `.claude/settings.json` and the template's, and the template test that checks skills' commands covers it.
- In the coordinator, `requirements.archived_path` finds a stamped file, or an unstamped one as older archives have, and the id scan accepts the stamp before `req-<id>`.
- `specs.md`, the `complete-change` skill and the Lifecycle in `specs/index.md` change in both copies. `specs/architecture.md` › Requirement storage follows, and a decision record covers the change.
- The README links to the archived v0.1 requirement, so renaming it means updating that link.
