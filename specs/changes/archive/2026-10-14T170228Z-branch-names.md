# Branch names that say who made them

## Requirement

As a developer, I want the coordinator's branches named for who made them rather than for the kind of change, so that I can tell agent work from my own at a glance and give it its own GitHub rules, without Git Flow's `feature/` and `fix/` ritual.

## Acceptance Criteria

1. A requirement's new branch is `agent/req-<id>-<slug>`, for a feature and a fix alike.
2. A template sync's new branch is `agent/template-sync-<task id>`.
3. A requirement whose branch already exists keeps it, and its tasks, reviews and pull request carry on as before.
4. The `implement` skill no longer tells a session to name a branch `feature/…` or `fix/…`.

## Out of scope

- Branches made outside the coordinator, which it doesn't name.
- Renaming existing branches.
- Removing a requirement's kind, which its page still shows.
- Release branches.

## Implementation Notes

- The names come from `worktrees.requirement_names` and `worktrees.task_names`.
- The `implement` skill, in both copies, says to name a new branch after the work: `req-<id>-<slug>` when the requirement has an id.
- A decision record supersedes ADR-012's naming. `specs/architecture.md`'s branch table and `CLAUDE.md` invariant 1 follow.
- A repository that has a branch called `agent` can't also have `agent/…`: git refuses, and the start fails with git's reason.
