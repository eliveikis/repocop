How this works

Each requirement in each repository is in the first stage that applies, read from the repository itself and GitHub, however the work was done. Delivered: archived in the past week, in the checkout or on the default branch on origin as last fetched. In review: a branch named after it has an open pull request. In progress: such a branch has commits that default branch lacks, or a RepoCop task is active on it. To do: everything else in its requirements folder. A branch is named after a requirement when its name is the requirement's, alone or after its last /, as bulk-import and agent/bulk-import are for bulk-import.md. Branches are as of each checkout's last fetch: Fetch all brings them up to date.
