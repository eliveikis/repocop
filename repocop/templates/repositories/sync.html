How this works

Compares the repo template at {{ settings.template_dir }} with what {{ plan.ref }} has committed, as of the last fetch: where a merged pull request lands. Picked files are committed on a new branch from there, in a RepoCop-owned worktree; the checkout at {{ repository.primary_path }} human-owned isn't touched.

{% if not plan.up_to_date %}

The template is the authority, so every file it offers is picked: missing files to be created, differing ones to be overwritten, merged files to be brought up to date, and files it no longer ships to be deleted. A merge adds what the template has and takes the template's values, and keeps what only the repository has. Untick a file to keep the repository's version. A starter file, once the repository has it, is its own and isn't offered. Only a file carrying the template's managed by template marker is offered for deletion: one without it is the repository's own, whatever its path.
